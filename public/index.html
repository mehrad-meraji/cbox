Two modes

Pick your workflow

One-shot for automation and scripting. Session for interactive, persistent work.

run

One-shot mode

Fire a prompt, stream output, exit with container's exit code. Pipe it, script it, automate it.

$ cbox "refactor auth to JWT"
$ cbox run -j "find TODOs" | jq
$ cbox run -f task.md --mount ./src
session

Persistent session

Interactive Claude Code backed by tmux on the host. Disconnect and reconnect anytime — session survives.

$ cbox session --name refactor
$ cbox list
$ cbox attach refactor
Features

What's inside

cbox is a thin coordinator. Docker, tmux, and Claude Code do the heavy lifting.

01

Docker isolation

Every run is a throwaway container. Nothing touches your host unless you mount it.

02

tmux persistence

Sessions survive terminal disconnects via host-side tmux. Reattach by name or ID.

03

MCP + skills

Host ~/.claude mounted read-only. localhost URLs rewritten to host.docker.internal.

04

agent-browser

Chrome baked into the image. Headless browser automation in every container.

05

JSON output

Use -j for structured output. Always valid JSON, even on failure.

06

Raycast

Script Commands for listing, attaching, and running prompts without a terminal.

07

Secure

API key by reference only. ~/.claude read-only. MCP patches written to tmpdir.

08

Zero config

Image builds on first run. Rebuilds only when CLI version or MCP packages change.

Commands
cbox "<prompt>"One-shot (implicit)

cbox run -j "<prompt>"JSON output
cbox sessionStart interactive session
cbox session --name <n>Named session
cbox listList active sessions
cbox attach <id|name>Reattach
cbox kill <id|name>Kill session
cbox buildForce rebuild image
Flags
--mount <path>Mount into /workspace (rw)
--mount <path>:roMount read-only
--env KEY=VALUEPass env var (repeatable)
--no-configSkip ~/.claude mount
--no-browserSkip agent-browser
-f, --file <path>Read prompt from file
-j, --jsonJSON output envelope
